### 로컬 DB 만들기
**도커(`oracle` 컨테이너)를 쓰는 경우**
- 프로젝트 폴더에서 `bash db/reset_local.sh`. 비밀번호는 실행할 때 입력합니다. 오류가 나면 그 파일에서 멈춥니다.

**도커 없이 로컬 Oracle을 쓰는 경우 (DBeaver)**
1. DBeaver에서 `ojj` 계정으로 연결합니다.
2. `01_schema.sql`부터 `07_test_screens.sql`까지 **번호 순서대로** 파일을 열고 **Alt+X**(스크립트 실행)를 누릅니다. Ctrl+Enter는 한 문장만 실행하니 쓰지 않습니다.
3. `01_schema.sql` 맨 앞의 `DROP TABLE` 줄에서 **ORA-00942(테이블 또는 뷰가 존재하지 않습니다)**가 나면 지울 테이블이 없다는 뜻이라 정상입니다. 오류 창에서 **[Ignore All]**을 누릅니다. 그 밖의 오류는 팀에 알려 주세요.
4. `05_test_team.sql` 끝의 확인표에 팀별 진행 사업 5줄이 나오면 끝입니다.

**서버**: `~/db`에 최신 파일을 올린 뒤 `bash reset_demo_db.sh`. 새 코드를 먼저 배포하고 실행합니다.

## DB 변경 규칙
1. DB 구조가 바뀌면 같은 PR에서 `01_schema.sql`, 시드(02~07), 테이블정의서, ERD를 함께 고칩니다.
2. **쓰지 않게 된 컬럼·테이블은 남겨 두지 않습니다.** 코드·Mapper XML·화면에서 안 쓰는 것을 확인하고 `01_schema.sql`에서 지웁니다.
3. PR 설명에 "DB 변경 있음(재생성 필요)"과 바뀐 테이블·컬럼을 적습니다. 머지 후 각자 로컬 DB를 다시 만듭니다 (도커는 `reset_local.sh`, 도커가 없으면 DBeaver로 01~07).
4. 패치를 만들 때(데이터를 유지해야 할 때): 새 코드를 먼저 배포한 뒤 실행하고, 지우는 패치는 서버 백업 테이블을 먼저 만듭니다. 패치 머리말에 대상·내용·백업 방법을 적습니다.
5. **SQL 파일은 DBeaver와 SQL*Plus(도커 스크립트) 둘 다에서 돌아야 합니다.** 그래서 파일 안에 아래를 쓰지 않습니다.
   - `SET ...` 같은 SQL*Plus 명령 (도커 스크립트가 실행할 때 앞에 붙입니다)
   - `/` 줄과 PL/SQL 블록(`DECLARE`·`BEGIN ... END;`). 반복이 필요하면 `INSERT ... SELECT`(`CONNECT BY LEVEL` 등)로 씁니다.
   - 문자열 안의 `&`. `'A' || CHR(38) || 'B'`처럼 씁니다. 주석에도 쓰지 않습니다.
   - 한 문장 안의 빈 줄 (DBeaver가 빈 줄에서 문장을 끊을 수 있습니다)
